# Guide screenshots

Generated by the capture harness, `frontend/scripts/capture-guides.mjs`.
Filenames are referenced from `content/guides/*.md`. Until a screenshot exists,
its guide shows a labelled placeholder rather than a broken image.

## Kept up to date

The **Guide screenshots** workflow (`.github/workflows/guide-screenshots.yml`)
runs the harness as a release step: it is dispatched by hand from the Actions
tab on the release branch before releasing (there is no schedule). When any
image changed it opens (or updates) a pull request from `chore/guide-screenshots`
into that release branch for a person to look over: a changed screenshot may mean a guide's text needs to
follow the UI too. A changed image never fails the run; a capture step that no
longer matches the app does.

## Running it locally

```bash
npx playwright install chromium            # once; playwright is a devDependency

# The served bundle must be the auth-disabled build, or every shot would be the
# sign-in page. The harness refuses an auth-enabled server or bundle.
VITE_AUTH_DISABLED=true npm run build

# From the repo root: single-user mode, in-memory database, samples seeded.
AUTH_DISABLED=true SEED_SAMPLES=true python -m uvicorn backend.main:app --port 8000

BASE_URL=http://localhost:8000 npm run capture:guides
```

`ONLY=<prefix>` re-captures just the shots whose filename starts with that
prefix — e.g. `ONLY=ccf` — which is much faster when iterating on one guide.

## Notes

- Shots of sample data run first, before any fixture exists, so no fixture can
  appear in a list page. The harness then seeds the datasets, models and
  diagrams the other guides need through the API (rather than automating fragile
  canvas gestures) and **deletes them afterwards**. Don't disable the cleanup.
- Each shot is checked: not the sign-in page, before and after its steps, and
  not an empty image. One broken shot doesn't stop the rest; the run fails at
  the end and names it.
- Anything that runs `npm run build` **without** `VITE_AUTH_DISABLED` (building
  the marketing bundle, prerendering) overwrites `dist` with the auth-enabled
  app. Rebuild auth-disabled before capturing again.
