# Guide screenshots

Generated by the capture harness. Filenames are referenced from
`content/guides/*.md`; re-run after UI changes so the guides stay in sync. Until
a screenshot exists, its guide shows a labelled placeholder rather than a broken
image.

## Running it

```bash
npm i -D playwright && npx playwright install chromium   # once

# IMPORTANT: the served bundle must be the auth-disabled build, or every shot
# is just the sign-in page. (The harness now fails loudly if it isn't.)
VITE_AUTH_DISABLED=true npm run build

BASE_URL=http://localhost:8000 npm run capture:guides
```

`ONLY=<prefix>` re-captures just the shots whose filename starts with that
prefix — e.g. `ONLY=ccf` — which is much faster when iterating on one guide.

## Notes

- The harness seeds real datasets, models, and diagrams through the API (rather
  than automating fragile canvas gestures) and **deletes them afterwards**. The
  local dev DB is the production one, so leftover fixtures would be visible to
  real users — don't disable the cleanup.
- Anything that runs `npm run build` **without** `VITE_AUTH_DISABLED` (building
  the marketing bundle, prerendering) overwrites `dist` with the auth-enabled
  app. Rebuild auth-disabled before capturing again.
